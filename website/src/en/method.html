Every viewer is measured with the same tool, from the outside and without touching the programs. The tool is part of the source code (crates/blinzel-race); every measurement can be reproduced.

Test images

24 JPEGs of 24 megapixels and about 8 MB each, as from a typical camera. Every image has its own base colour; consecutive images always differ.

Detection

Through the Desktop Duplication API on Windows and ScreenCaptureKit on macOS the tool sees every frame that reaches the screen, with its presentation time. A grid of sample points recognizes from the base colour which image is visible, on every monitor. On macOS the tool starts every viewer through Launch Services (open -a), the way Finder opens a file with an app.

Measurements

  • Opening: from process start until the first image is visible. Warm: program and image are in the file cache. Cold: the file cache is emptied first.
  • Next image: after 1.5 seconds of rest, one arrow key press until the next image is visible.
  • Key repeat: 20 presses at 30 Hz, like a held key. Counted: how many images actually appear.

Fairness

  • Same machine, same files, every viewer with default settings; the versions are part of the results.
  • Several repetitions; reported are the median and the 95th percentile, the raw data is published.
  • A first, uncounted start loads every program into the cache.

Measure yourself

blinzel-race corpus images creates the images, blinzel-race run images --json result.json measures every viewer found. Cold starts need administrator rights (--cold; on macOS the tool asks for the password once). On macOS the terminal also needs the Screen Recording and Accessibility permissions (System Settings, Privacy & Security).

Open images, page, resize.

An image viewer for Windows, macOS and Linux, built for short times when opening and paging through images. It also resizes many images at once and takes screenshots. No toolbars, no ads, no telemetry.

Features

Viewing

The window appears with the image already on it. Images are decoded only as large as the screen needs; the next images wait as GPU textures in the direction you page. Image files stay unchanged: cutouts are only written as new files through “Save as”, losslessly from JPEG where possible.

Resize many images

Ctrl+B opens the dialog; drag images and folders into it. Long edge, width, height, box or percent; JPEG, PNG, WebP or AVIF; EXIF and the colour profile can be kept, GPS removed. A name pattern shows every new name in advance. Source files are never overwritten.

Screenshots (Windows)

The Print key freezes the screen: drag a region, click a window or press Enter for the whole screen. The screenshot is saved as PNG in “Pictures\Screenshots”, optionally also copied, and opens in the viewer. E hands it to your editor.

Controls and shortcuts

There are no toolbars. The menu (☰) sits top left; minimize, maximize and close sit top right. On a Mac the system's window buttons sit there, the menu goes right and is in the menu bar as well. Everything else is in the menu or on a key; on a Mac ⌘ replaces Ctrl.

Screenshots in detail
  • Taking one: with the Print key while amigo-blinzel stays ready in the background (Settings → “Keep ready in the background”), or through the icon in the notification area: “Take screenshot…” or “Screenshot of the whole screen” for the monitor under the pointer.
  • The picture freezes at once, across all monitors. Dragging picks a region, a click the window under the pointer, Enter the whole screen; Esc cancels.
  • It is saved as PNG with the date in its name, by default in “Pictures\Screenshots”; the folder can be changed in the menu. Optionally the screenshot is also copied to the clipboard.
  • The screenshot then opens in the viewer. There is no editor of its own: E or “Edit with…” hands the image to the program of your choice.
  • Windows 11 gives the Print key to the Snipping Tool by default. Then Ctrl+Shift+Print works, or turn off Settings › Accessibility › Keyboard › “Use the Print screen key to open screen capture”.
  • macOS and Linux follow.
Resizing many images in detail
  1. Menu → “Resize images…” or Ctrl+B (⌘B on a Mac).
  2. Drag images or folders from the file manager into the dialog. A folder adds its images, not those of its subfolders. Remove single files with ×.
  3. Choose size, format and names, pick the output folder, start. Progress and a report appear in the dialog; “Open folder” shows the result.
  • Size: long edge, width, height, fit into a box, fill a box (centre crop) or percent. Small images are not enlarged unless you ask. Scaling is Lanczos3 in linear light with premultiplied alpha; an unsharp mask can sharpen afterwards.
  • Formats: JPEG, PNG, WebP (lossy or lossless), AVIF or “same as source”. Sources without an encoder (GIF, BMP, TIFF, HEIC, JPEG XL, RAW) become JPEG, or PNG when they have transparency. For animations the first frame is used.
  • Metadata: EXIF is kept and adjusted (orientation, pixel size, without the embedded thumbnail and maker notes). GPS coordinates can be removed. The colour profile is carried over unchanged, also into WebP and AVIF.
  • Files: source files are never overwritten. If a name exists, the new file gets “ (2)” appended; every file is written completely before it is put in place.
  • Speed: all cores work in parallel, within a memory budget; JPEGs shrink while decoding (DCT scaling). Measured with blinzel-bench batch: 8.6 photos per second (12 MP to 1920 px, 4 cores) against 2.1 with ImageMagick on the same files.

How it works
  • Decoding at screen resolution: JPEGs are decoded with DCT scaling straight into YCbCr planes; the GPU does colour conversion and scaling.
  • An own JPEG decoder spreads Huffman decoding over all cores, even without restart markers, and is byte-identical with libjpeg-turbo.
  • Prefetching in paging direction, with priorities and cancellation.
  • Parallel start: window, GPU and decoder start at the same time.
  • Native on every platform: Win32 and Direct3D 11 on Windows, AppKit and Metal on macOS, Vulkan (wgpu) on Linux. No runtime, no framework in between.

How we measure

Every viewer is measured with the same tool, from the outside and without touching the programs. The tool is part of the source code (crates/blinzel-race); every measurement can be reproduced.

  • Test images: 24 JPEGs of 24 megapixels and about 8 MB each, as from a typical camera. Every image has its own base colour; consecutive images always differ.
  • Detection: through the Desktop Duplication API on Windows and ScreenCaptureKit on macOS the tool sees every frame that reaches the screen, with its presentation time. A grid of sample points recognizes from the base colour which image is visible. On macOS the tool starts every viewer through Launch Services (open -a).
  • Opening: from process start until the first image is visible. Warm: program and image are in the file cache. Cold: the file cache is emptied first.
  • Next image: after 1.5 seconds of rest, one arrow key press until the next image is visible.
  • Key repeat: 20 presses at 30 Hz, like a held key. Counted: how many images actually appear.
  • Fairness: same machine, same files, every viewer with default settings; the versions are part of the results. A first, uncounted start loads every program into the cache.

Measure yourself: blinzel-race corpus images creates the images, blinzel-race run images --json result.json measures every viewer found. Cold starts need administrator rights (--cold; on macOS the tool asks for the password once). On macOS the terminal also needs the Screen Recording and Accessibility permissions (System Settings, Privacy & Security).

First start, installation and updates

Windows

The file is not signed with a code signing certificate, so Windows SmartScreen shows “Windows protected your PC” at the first start: click More info, then Run anyway. To make amigo-blinzel the default for images, use Windows Settings; the setup opens the page if you like. Uninstall: Settings → Apps → Installed apps.

macOS

The app is not notarized by Apple, so macOS reports at the first start that it cannot check it. On macOS 14: Control-click the app in Finder, choose Open and confirm. From macOS 15: open it once, then System Settings → Privacy & Security → Open Anyway. Or in Terminal: xattr -dr com.apple.quarantine /Applications/amigo-blinzel.app. Make it the default through “Get Info” → “Open with” → “Change All”.

Linux

tar xzf amigo-blinzel-linux-x64.tar.gz
./amigo-blinzel/blinzel --install

This puts the program in ~/.local/share/amigo-blinzel, a blinzel command in ~/.local/bin and an entry in the application menu with “Open with” for images. To make it the default image viewer: xdg-mime default amigo-blinzel.desktop image/jpeg image/png image/webp image/avif. Uninstall: blinzel --uninstall.

Checksums

The checksums of all files are in SHA256SUMS, signed with the project's release key. On Windows: Get-FileHash amigo-blinzel-setup-x64.exe; on macOS and Linux: shasum -a 256 or sha256sum.

Updates

amigo-blinzel asks GitHub at most once a day whether there is a new version and installs it silently; it takes effect at the next start. To turn it off: auto_update = false in settings.toml, on Windows in %APPDATA%\amigo-blinzel, on macOS in ~/Library/Application Support/amigo-blinzel, on Linux in ~/.config/amigo-blinzel.

amigo-blinzel resizes whole folders in one go: for the web, for mail, for the photo book. Right in the viewer, the same on every platform.

How it works

  1. Mark images in the grid (G): Ctrl+click, Shift+click, Ctrl+A. Without marks the dialog takes the whole folder.
  2. Menu → “Resize images…” or Ctrl+B (⌘B on a Mac).
  3. Choose size, format and names, pick the output folder, start. Progress and a report appear in the dialog; “Open folder” shows the result.

Size

  • Long edge, width, height, fit into a box, fill a box (centre crop, i.e. to an aspect ratio) or percent.
  • Small images are not enlarged unless you ask.
  • Scaling is Lanczos3 in linear light with premultiplied alpha: no dark fringes at edges, no grey halos around transparency. An unsharp mask can sharpen afterwards.

Formats

JPEG, PNG, WebP (lossy or lossless), AVIF or “same as source”. Sources in formats without an encoder (GIF, BMP, TIFF, HEIC, JPEG XL, RAW) become JPEG, or PNG when they have transparency. For animations the first frame is used.

Metadata

EXIF is kept and adjusted: orientation set to normal (it is in the pixels then), the new pixel size, without the embedded thumbnail and maker notes. GPS coordinates can be removed. The colour profile is carried over unchanged, also into WebP and AVIF.

File names

A pattern of placeholders sets the name; the dialog shows the first name as an example.

PlaceholderMeaning
{name}source name without extension
{n}, {n:3}running number, optionally with leading zeros
{w}, {h}width and height of the result
{date}date taken from EXIF, else the modification date
{ext}extension of the source

Source files are never overwritten. If a name exists, the new file gets “ (2)” appended; every file is written completely before it is put in place.

Speed

All cores work in parallel, within a memory budget. JPEGs shrink while decoding (DCT scaling) where the target allows. Measured with blinzel-bench batch: 8.6 photos per second (12 MP to 1920 px, 4 cores) against 2.1 with ImageMagick.
